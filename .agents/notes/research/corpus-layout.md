# 验证材料目录与边界

2026-10-18。用户要求落实八类 corpus 和各类 case 的文件结构，同时延续单个 case 尽量小的
选择。目录组织、案例与测试入口见 [corpus 说明](../../../corpora/README.md)；
本笔记记录本轮的取舍及证据，不维护另一份格式规范。

八类结论来自本任务中用户提出的差分检测、生成发现、归约，以及后续确认的生成正确性、
判定、重放、执行可靠性、批量验收分类。使用共享 case 池和八份清单，避免每类复制同一源码
或预建八套执行框架。既有历史源码路径和生成案例格式保持不变。

新增 [#1326 候选](https://github.com/moonbitlang/moonbit-docs/issues/1326) 仅用作待接入的
差分与生成再发现目标。已核对上游报告的 UInt 可选值、移位和 native release 条件，
以及报告中的 `v0.10.15+943464bfa`。本轮未声称由 MoonSmith 暴露或生成器重新发现该问题。
生成规则与归约模型仍只有当前声明的 Int/Bool 子集；再发现定义中的 required_features
是前置需求，不是已提供能力。

受控归约原例取自本轮实际执行 `run --seed 7` 保存的生成材料，
生成器为 `template-rules-v1`，节点预算 128、深度预算 6、构造次数预算 256；
实际为 128 节点、深度 6、140 次构造。导出时仅按仓库格式统一文件末尾换行，
没有改写程序结构，也没有覆盖运行目录中的原始源码。
该次当前三配置正常一致，并非编译器失败；根表达式调用是后续受控判据的定义，
归约入口尚未接入。真实归约定义目前引用 #1326 的短触发候选，
仍需要较大原例和语言操作适配，不能据此报告“大到小真实归约成功”。

本轮执行已有历史参考案例、生成性质输入和模型观察分类；
目录校验只检查定义、输入和引用，不能代替 pending 条目的产品行为。
对未知入口、越界路径、重复案例、以及把模型入口标为真实工具链的清单，校验应拒绝。
模型观察使用当前 Contracts 的 JSON 编码，缺省的可选注入字段省略，未伪造真实命令执行。

这是已有验收目标的材料组织与测试接入，不改变公共 CLI、生成材料兼容性或失败保持条件，
按 FP-0000 不新增提案。没有新增外部依赖、跨仓库调用或算法比较入口。
