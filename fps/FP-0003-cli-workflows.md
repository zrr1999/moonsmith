# FP-0003: MoonSmith 命令行工作流与结果约定

## 摘要

设计 MoonSmith 的命令行产品接口：启动新的差分测试任务、读取结果，以及再次执行已保存的案例。语言、比较与证据规则继续由 [FP-0002](FP-0002-moonbit-semantic-contract.md)负责。

MoonSmith 采用完整流程优先的工作流；完整 SemaForge 阶段采用可组合阶段命令。无参数只显示帮助，`run` 执行有限测试任务，默认一个样本；`replay` 重执行保存的材料。 `--config FILE` 显式读取 TOML，重复的 `--set KEY=VALUE` 使用相同字段及 TOML 值语法覆盖配置。默认值、文件与命令行汇入同一份有效配置并统一校验；实际种子、预算、计划配置及结果可核对。原始案例与执行记录追加保存，任务报告区分比较结论、操作错误和未完成范围。退出码沿用一致 `0`、分歧 `2`、比较未完成 `3`、参数或操作错误 `1`。

## 动机

差分测试涉及程序生成、多配置执行、结果比较和证据保存。使用者需要知道如何启动一次测试、理解结果并再次执行保存的案例，库能力本身不能替代这些命令行约定。

FP-0002 已约定差分比较、有效预算和保存后再执行的要求，但没有定义命令树、输出界面及退出状态。使用者和调用脚本需要明确区分已发现分歧、执行证据不足和工具自身操作失败；一个笼统的成功或失败状态不足以指导调查。本提案约定这些命令行接口。

## 设计

### 与已有提案的分工

| 决定 | 归属 |
| --- | --- |
| 模块职责和依赖方向 | [FP-0001](FP-0001-workspace-modules.md#包的职责与依赖) |
| 程序生成、合法性、差分判定与必要执行证据 | [FP-0002](FP-0002-moonbit-semantic-contract.md#设计) |
| 使用者执行哪些操作、命令如何组合、参数及结果如何呈现 | 本提案 |

本提案约定命令的输入、可观察结果、错误与产物。`run` 内部有哪些处理阶段、如何组织以及采用什么算法，由相应组件的设计与实现负责。内部流程调整只要保持这些对外约定，就不需要修改本提案；命令入口也不要求与内部阶段一一对应。

FP-0002 保留预算可配置和保存后重执行的要求；本提案确定配置入口、覆盖关系及可观察结果，不重新定义比较结论。库和应用入口可以先独立验证，命令行验收仍须经过实际可执行入口。公开配置字段以任务所需为限，不因为存在内部参数就增加同名专用 CLI 选项。

CLI 的模块职责遵循 FP-0001；本提案的验收以实际命令的输入与输出为准。

### 产品原则与决策总表

MoonSmith 优先提供可直接使用的默认配置；完整 SemaForge 的通用、可组合入口另行设计。单样本与多样本统一为有限任务，配置文件和命令行覆盖共用字段。起始种子使用 `seed_start` 配置，例如 `--set seed_start=42`。

| 决策项 | MoonSmith 的选择 |
| --- | --- |
| 工作流 | 一次调用交付新测试的结果与可重放材料，保存材料通过 `replay` 重执行 |
| 启动 | 无参数显示帮助，`run` 才启动测试 |
| 样本数量 | 有限正整数，默认一个；单例是同一任务模型的默认值 |
| 配置入口 | `--config FILE` 加可重复的 `--set KEY=VALUE`，不自动发现配置文件 |
| 覆盖关系 | 内置默认值、显式文件、命令行从低到高；重复设置最后一次生效，数组整体替换 |
| 随机种子 | 省略起点时自动选择并记录，显式起点与样本数形成连续范围 |
| 编译配置 | 默认内置组合，可选择其有效子集，记录完整计划及顺序 |
| 结果 | 覆盖完整计划，保存比较结论、实际状态与未完成原因 |
| 产物 | 原始输入配置与实际生效配置分别保存，原案例与旧尝试不覆盖 |
| 退出码 | 操作错误 `1`、分歧 `2`、比较未完成 `3`、全部一致 `0`，按此优先级汇总 |
| 重放 | 使用当前工具链执行保存材料，追加记录并提示已知版本变化 |

这些选择遵守 FP-0002 的程序合法性、比较与证据契约，不承诺仅凭种子跨版本重生成。

### 按产品阶段安排工作流

工作流与[三阶段路线图](../ROADMAP.md#三阶段方向)一致：MoonSmith 采用完整流程优先的工作流；第二阶段提取公共库时保留该工作流；完整 SemaForge 产品采用可组合阶段命令，届时设计材料交接、参数归属和阶段失败处理。

MoonSmith 在后续阶段继续提供专用体验。本提案不提前定义 SemaForge 命令树或材料交接格式。阶段命令不意味着支持任意外部源码，其命令及交接范围在 SemaForge 产品阶段另行设计。

参考 [cargo-fuzz 的运行入口](https://rust-fuzz.github.io/book/cargo-fuzz/guide.html)和 [libFuzzer 对生成运行与已有输入重跑的区分](https://llvm.org/docs/LibFuzzer.html#options)，可借鉴围绕使用任务组织入口的方法；这些工具的测试对象不同，不能据此直接套用其命令表。

### 有限测试任务

`run` 的职责是执行一次新的差分测试任务。样本数默认为一，显式配置可以扩大有限范围，每个样本仍有自己的多配置观察、案例和执行记录。任务不因发现分歧而删去其余计划样本。单个样本操作失败需保留该种子及错误后继续；无法保存样本记录时停止，明确说明未完成范围。任务报告区分计划数、已尝试数、各比较结论与发生操作错误的样本数；操作错误可以与比较结论重叠。

该选择参考 [nextest 的统一运行与筛选](https://nexte.st/docs/selecting/)及 [k6 的配置驱动运行](https://grafana.com/docs/k6/latest/using-k6/k6-options/how-to/)：数量和配置可以参数化同一操作。`batch` 只描述执行方式，额外入口会重复新测试任务的含义。无需为当前只有执行操作的任务增加 `task run` 层级。 `replay` 的输入及目标不同，继续独立使用保存材料，不按生成种子重新生成源码。

### 帮助、启动入口与后续扩展

| 调用 | 行为 |
| --- | --- |
| `moonsmith`、`moonsmith --help` | 显示帮助与常用示例，不创建案例或启动编译 |
| `moonsmith run` | 以默认配置执行一个样本的任务 |
| `moonsmith run --set seed_start=42` | 指定起始种子，其他值使用默认配置 |
| `moonsmith run --config acceptance.toml` | 读取显式任务文件后执行 |
| `moonsmith run --config acceptance.toml --set sample_count=10` | 覆盖文件中的样本数后执行 |
| `moonsmith replay CASE_DIR_OR_ATTEMPT_DIR` | 执行保存的实际源码，向原案例追加本次记录 |

`run --help` 与 `replay --help` 显示用法，不启动任务。帮助列出已公开的配置键、类型、单位及适用范围，并提供字符串与数组的 shell 引号示例。非法、未知、缺值及重复的文件参数在启动测试前明确拒绝；只接受一份显式文件，重复覆盖通过 `--set` 表达。后续扩展须同步帮助、文档与行为验收，不增加占位命令。

### 种子的选择与记录

`seed_start` 是首个生成种子，`sample_count` 是正整数样本数，第 `i` 个样本使用 `seed_start + i`，其中 `i` 从零开始。显式起点及整个范围必须落在有符号 32 位整数内；不能通过整数环绕把越界范围变成另一批种子。未指定起点时，在其他配置校验通过后从系统熵选出能容纳完整范围的起点，选择失败报告错误。

终端与案例记录保留每个样本实际使用的种子；实际生效配置保存选定起点及完整预算，失败样本也记录其种子。显式种子非法时不能静默改成自动选择。相同生成器版本、种子和有效配置产生相同程序；不同种子可能产生同一程序，种子不承担唯一 ID。 `replay` 使用保存的程序，不重新选择种子或调用生成器。

### 计划编译配置

默认使用内置组合，`execution.configurations` 可以指定其中至少两个不同且受支持的配置，保留用户顺序。具体支持范围由 [FP-0002](FP-0002-moonbit-semantic-contract.md#差分比较与证据) 的分工及实际工具链确定，并在帮助中列出。配置不可用、失败或超时都保留原始事实，不能删除未完成成员后报告全部一致。执行前展示计划，各样本保存自己的完整计划及观察。配置入口不接受任意外部编译命令，也不负责自动安装或重建工具链。

### 执行完成与结果交付

一次调用交付全部计划配置的实际状态和已取得的证据。已发现某项分歧不缩减其余计划配置的结果交付范围，使用者无需仅为补充其他配置结果再次启动测试。

配置编译失败、崩溃或超时时，结果保留其实际状态。发生导致任务无法完成的操作错误时，如实报告错误和未完成范围，不将缺失配置从计划中移除。

一次结果交付同时包含比较结论、各计划配置的执行状态和保存材料的位置。配置未取得有效结果时，仍可交付差分不一致或比较未完成的记录；只有全部计划配置都有有效且相同的结果，才可报告本次结果一致。保存失败时报告已有结论及保存错误，不能声称案例已完整归档。

### 公开参数与配置

`--config FILE` 只读取用户明确指定的一份 TOML 文件。文件允许省略字段，未提供部分沿用内置默认值；未知字段仍报错。`--set KEY=VALUE` 可重复，使用与文件相同的字段路径和 TOML 值语法，按命令行顺序覆盖。数组整体替换，不隐式追加；一个 `--set` 只设置一个叶子字段。字段类型、单位和预算范围复用同一校验，命令行覆盖只接受配置字段路径，不设置字段别名。

`generation.generator` 选择语言适配器支持的生成器版本。内置默认版本、文件及覆盖值按相同优先级合成，实际标识写入生效配置和每个生成案例；未知版本在输出创建和生成前拒绝。已保存源码的 `replay` 继续使用实际材料，不通过该字段重新生成，也不要求原生成器仍可用。

文件、默认值及覆盖值先合成为一份任务配置，再检查完整种子范围、计划配置及各预算。类型错误、未知键、非法范围及不支持的组合须在创建输出和生成程序前报错。不额外读取环境变量、搜索父目录配置，或把配置中的字符串作为命令执行。

文件内的相对输出路径以实际配置文件所在目录为基准；默认值和命令行覆盖的相对路径以调用时的当前目录为基准。绝对路径直接使用。记录实际生效的路径，不因配置副本迁入产物目录而重新解释原来的相对路径。原输入文件按原样保存，实际生效配置另存，包含选定的起始种子、覆盖后的预算、计划及路径，不修改用户文件。

语法借鉴 [Cargo 的 TOML 键值覆盖](https://doc.rust-lang.org/cargo/reference/config.html#command-line-overrides)，但本提案保留读取文件与设置字段两个明确参数，不采用一个 `--config` 同时解释路径与键值的方案。

### 结果与产物

正常结果显示简短摘要，出现分歧或执行失败时自动展开关键结果与原因，完整证据保存在案例中。使用者可以据此直接判断调查方向。任务摘要包含计划数、已尝试数、比较结论与操作错误计数及材料位置；样本摘要包含种子、计划配置与有效结果数。操作失败时只报告实际取得的信息，不编造路径或保存成功状态。

生成运行与保存案例重执行采用相同的结果和退出码约定。退出码在本次命令结束时返回，下表中 `0`、`2`、`3` 均要求本次结果与必要证据保存成功：

| 情况 | 退出码 | 使用者需要知道的事实 |
| --- | --- | --- |
| 本次结果一致 | `0` | 所有计划配置均取得有效且相同的结果；不表示已证明编译器正确 |
| 差分不一致 | `2` | 展示结果不同的配置及其关键结果，同时列出未取得有效结果的配置和原因 |
| 比较未完成 | `3` | 尚无有效分歧，但计划配置的有效结果不足；列出缺失结果、失败阶段和原因 |
| 参数或操作错误 | `1` | 包括参数、生成、保存等操作失败；说明测试是否启动、失败阶段，以及已有材料位置 |

有两个配置结果不同而第三个配置超时时，保存成功后返回 `2`，摘要同时呈现分歧和超时。两个配置结果相同而第三个配置超时时，保存成功后返回 `3`。已经发现分歧但保存失败时返回 `1`，同时说明分歧和保存错误，不能用操作错误掩盖已取得的判断。参数校验或生成失败尚未产生可执行案例时返回 `1`；若已选定种子，失败报告保留该种子。帮助正常显示后返回 `0`，不受上述测试执行与保存条件约束。

多样本任务按操作错误 `1`、分歧 `2`、比较未完成 `3`、全部一致 `0` 的优先级汇总；样本比较结论与操作错误分别统计，保存失败不能掩盖已观察到的分歧。样本记录先保存，任务报告及完成标记最后保存；缺少完成标记时不能报告整个范围已完整交付。

退出码表示命令的可观察结果，非零不自动等同于工具崩溃或已确认的编译器缺陷。

任务可显式开启有限的等价变换检查。原程序和经过完整检查的变换程序使用同一配置计划与观察协议，Engine 将其正常输出统一参与差分；跨程序的不一致同样返回 `2`，不要求参考值。样本数仍以原程序计，完整比较覆盖所有计划程序和配置；基线接受继续针对原程序。原程序与变换程序分别追加执行记录，关系和总体结论先写本地报告，不覆盖单次执行事实。重放每份保存源码不自动重建等价组；跨程序归约需保持原变换关系，当前单程序归约不适用于此。

构建失败不产生正常输出值，仍按比较未完成处理。已保存的构建异常可由工具链专用判据触发有界归约，候选须保持目标诊断和声明的控制条件，并对选定结果独立确认。这类归约附在原始比较之后，不把构建失败转换为输出分歧；保存成功时仍返回 `3`。搜索及确认复用追加式执行记录，判据、候选关系和结果可先保存在本地报告中，不要求为此引入新的版本化归档协议。归约操作或必要记录保存失败按操作错误处理。stdout/stderr 分工、机器可读输出和具体文案留待后续 PR；终端摘要不替代原始输出和完整证据。内部验证中的故障注入须明确标识。报告应明确结论对应的材料及其完成状态；附加产物不覆盖原始材料与以往结论。任意外部源码执行仍不在当前命令范围内。

### 保存案例重执行

重执行使用保存的实际程序、输入及配置，追加本次观察并保留原记录，不重新选择种子或通过生成器重建程序。完整归档格式及产物路径的传入方式仍按实际需要另行设计。

重执行使用当前工具链，无需先恢复原工具链。这样既可继续调查旧案例，也可检查升级后是否仍存在分歧。每次记录实际工具链身份与环境信息；与原执行相比有已知版本变化时明确提示。无法取得版本信息时保留探测失败事实，不能声称两个版本一致。首版不承担自动安装或重建历史工具链环境的职责。

比较结论来自本次各配置之间的观察，历史结果保留供对照。新版工具链下结果一致，只表示本次未观察到分歧；仍有分歧也不自动证明与原执行具有相同缺陷根因。当前工具链的编译失败、崩溃和超时按实际状态记录，不因版本变化而改写历史结论。

重执行入口接受用户选择的已保存材料路径，结果明确指出本次使用的材料及新增记录位置。材料损坏、缺失或格式不受支持时报告错误，不用其他材料替代用户指定的输入。

## 兼容性

本提案首次约定 MoonSmith CLI 的工作流、配置入口与结果，沿用 FP-0001 的职责边界和 FP-0002 的生成、比较与证据约定。命令编排、结果呈现和退出码须满足这些前序契约。

后续扩展以届时已确立的 FP 约定及正式对外接口评估兼容性影响。

## 验证

以下为命令行接口的验收要求；文档检查通过不代表产品行为已经验收。

| 场景 | 应观察到的行为 |
| --- | --- |
| 首次使用 | 按帮助信息完成所选工作流，并能找到结果和原始证据 |
| 帮助与启动 | 无参数及 `--help` 显示帮助，不执行编译或创建案例；`run` 才启动新案例测试 |
| 有限任务 | 默认一个样本，显式数量按连续种子执行；每例独立存证，普通样本错误不丢失后续分母 |
| 自动种子 | 未指定种子时选择有效值，终端与案例记录中的值一致；生成失败报告保留已选种子 |
| 指定种子 | 使用显式值；相同生成器版本、种子和有效配置产生相同源码；非法值或缺失值不回退为自动选择 |
| 计划配置组合 | 使用默认组合或有效子集，保留顺序；缺失或失败配置仍留在计划及证据中 |
| 结果覆盖范围 | 报告全部计划配置的实际状态；有分歧时仍交付其余配置的结果，操作错误时明确未完成范围 |
| 配置一致性 | 文件与命令行使用同一字段和类型，后者覆盖前者，数组整体替换；默认值及实际参数写入生效配置 |
| 配置错误与路径 | 未知键、类型错误、越界范围在输出创建前失败；相对路径按来源解释，原配置不修改 |
| 自动种子范围 | 起点选择能容纳完整样本数，熵不可用明确失败，实际起点保存后可核对 |
| 结果与退出码 | 保存成功时，一致返回 `0`、分歧返回 `2`、证据不足返回 `3`；参数、生成或保存错误返回 `1` |
| 分歧与不完整并存 | 两个有效结果不同、第三个配置超时，保存成功后返回 `2`，同时展示分歧和超时 |
| 保存失败 | 已知分歧和保存错误同时可见，返回 `1`，不报告完整交付 |
| 默认输出 | 正常结果显示简短摘要，异常自动展开关键结果或失败原因；完整证据仍可从保存材料查看 |
| 保存后再执行 | 命令使用保存材料产生新观察，不改写旧案例与旧结论 |
| 材料选择与错误 | 重执行用户指定的已保存材料；材料损坏、缺失或格式不受支持时给出具体错误 |
| 重放时工具链变化 | 允许使用当前工具链，记录实际身份并提示已知变化；本次结论与历史记录分别保留 |

具体配置字段及默认值由实现文档与帮助同步维护，输出流分工留给后续 PR。
