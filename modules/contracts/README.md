# MoonSmith Contracts

实现[共享契约](../../fps/FP-0001-workspace-modules.md#term-shared-contracts)，
包含语言无关的命令、进程结果、执行观察、异常指纹、判定、案例和执行记录。

`OracleResult` 以 Oracle、配置和阶段标识一项判断，结果区分满足、违反、不适用和证据不足。
`Assessment` 保存这些结果的不可变快照；完整性要求所提交的结果非空、无重复标识且无证据不足，
不会推断调用方未声明的检查。`FailurePredicate` 为原型的异常类别加上 Oracle 身份，
`PredicateStatus` 区分保持、不保持、不可判定和不适用。更复杂的关系判据由后续 Oracle 扩展。
`Assessment` 用于库内交互，`PredicateStatus` 也用于保存归约确认状态；
现有 `Attempt` 继续保存原型主结论与原始观察。

`Case` 保存原始生成配置与参考结果，`Attempt` 保存一次实际执行的工具链、命令和输出。
记录通过标准库 JSON 编解码；`format_version = 1` 标识参考案例格式。

原始进程输出与可选故障注入输出分别保存。数据结构不包含语言 AST 或宿主资源句柄。

## 差分记录

`Comparison` 表达无参考值的差分结果：全部配置一致、两个有效配置结果不同，或比较未完成。
它与已有参考判定 `Verdict` 分开表示，避免改变旧案例结论的含义。

`DifferentialCase` 与 `DifferentialAttempt` 使用 `format_version = 2`，不要求参考值。
案例包含 `GenerationRecord`（种子、生成器版本、有效预算和实际规模）、生成源码与构建文件、
观察协议、计划配置和执行超时；输入嵌入源码，程序无参数且 stdin 为空。
执行记录保存当前工具链和平台探测的 `ProcessEvidence`、各配置的原始观察及 `Comparison`。
版本 2 的重执行使用保存材料，不要求仍能运行当时的生成器，也不转换旧参考结论。

`DifferentialReduction` 是独立的版本 3 归约摘要，关联原始尝试、固定配置对、候选预算及计数、
最佳结果和独立确认尝试。`cost_model` 说明成本定义，`original_cost` 与 `best_cost` 保存
`ReductionCost` 的节点数、整数常量量级与源码字节数；顺序及计算语义由语言适配器解释。
节点数直接读取成本记录，不维护另一份副本。记录还明确停止原因、确认状态和操作错误，
`elapsed_ms` 保存搜索及独立确认的单调时钟耗时。
版本 1、2 的旧摘要保持原样；源码重放读取案例和尝试材料，不依赖归约摘要。
摘要升版不改变版本 2 的案例、尝试或原始生成记录，也不表示搜索可以恢复。

## 有限任务记录

版本 2 的 `TaskSample` 关联显式种子与结果：`TaskOutcome` 区分取得比较结果和操作失败。
取得结果时，`TaskObservation` 链接原始案例与尝试，并保留比较结论及可选操作错误。
因此已经观察到分歧但保存失败时，两项事实可以同时记录。

样本保留成功构造并完成内部检查的 `GenerationRecord`，生成失败时缺省；后续保存失败
不会把已经完成的内部检查改记为失败。`baseline_build` 区分构建正常退出、未正常退出和没有基线构建观察，
`comparable_results` 与 `planned_results` 保留有效结果数量和计划分母，`elapsed_ms` 记录样本处理耗时。

`TaskSummary` 的 `format_version = 2` 独立于单案例格式，保存任务名、计划与已尝试样本数、
各比较结论、操作错误、内部检查通过、基线构建尝试与接受、全部配置取得有效结果的计数，
以及处理样本至汇总前的单调时钟耗时。操作错误可以与比较结论重叠。
旧任务汇总保持原样，案例源码重放不读取任务汇总。
这些类型只描述事实，不读取 TOML、不调度执行，也不包含具体语言的生成预算类型。
