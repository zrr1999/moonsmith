# Engine 抽象骨架与最小实现

日期：2026 年 10 月 17 日。调研基线为 `359c755fe1bbee080669ca63daf494fbd92b758e`。
本文记录本轮已确认的取舍；设计由 [FP-0004](../../../fps/FP-0004-engine-execution-contract.md)
维护，实际 API 由模块 README 说明。

## 问题与来源

基线的 `ReductionSession` 已独立管理失败保持、原始程序、当前位置、最佳结果与预算。
`Reducer` 同时管理候选数组、枚举和接受后的重建，构造时只接受节点规模函数。
语言候选在完整检查之前过滤同节点程序，终端也用节点数相等推断没有改善，因而不能承载
`IntLiteral(2147483647)` 到 `IntLiteral(0)` 这样的常量简化。

前期[Engine 调研](engine-research.md)已给出操作、调度、局部搜索与公共引擎的分工。
[WDD 论文](https://arxiv.org/html/2411.19410v2)分别将权重用于分组以及概率搜索的排序和收益，
说明权重不能仅建模为通用分组开关。
[CDD 论文](https://arxiv.org/html/2408.04735v3)讨论避免重访与最小性之间的取舍，说明搜索停止
不能自动推导最小性。这些来源用于检验抽象的表达能力，不作为必须实现的算法清单。

## 已确认的选择

本轮用户确认先在既有 FP 中设计职责、组合约束及非规范性的 ADT 示意，实现采用朴素方法。
不要求交付 ddmin 或其他论文算法。组合使用结构，互斥能力使用 sum type，可替换行为通过
接口或回调连接；不冻结 MoonBit 签名、序列化计划或所有未来能力的配置表。

继续复用会话核心，将候选操作、局部枚举和固定操作调度分开。当前差分装配先枚举结构操作，
再枚举 Int 归零；接受后丢弃旧候选并从新程序重启操作顺序。两项操作共用原候选预算，
各自仍返回一次性构造的数组；没有把构造次数计入执行预算，也没有新增构造限额。

Engine 只调用比较函数。MoonBit 适配器定义节点数、整数常量绝对值之和与源码 UTF-8
字节数的字典序成本，完整检查与成本筛选共用候选出口，接受及最佳结果使用同一顺序。
绝对值在转为 Int64 后计算，首个常量操作仅将非零 Int 替换为 `0`。
旧参考路径继续按节点数排序，不在本轮合并两套程序表示或参考语义。

归约摘要升为版本 2，保存成本标识与前后成本；节点数读取成本字段，不重复保存。
报告按成本相等判断零进展。旧归约摘要不迁移，源码重放仍只读取原有案例与尝试材料。
原始执行、每个候选与一次独立确认继续各自保存，新证据保持原配置对分歧才允许接受。
