# FP-0003: MoonSmith 命令行工作流与兼容约定

## 摘要

单独设计 MoonSmith 的命令行产品接口：使用者如何启动测试、读取结果，以及
再次执行已保存的案例。命令组织、参数表达和旧入口迁移在本提案中讨论，遵循
[FP-0002](FP-0002-moonbit-semantic-contract.md)确定的包边界与交接契约。

提案作者已确认按产品阶段安排工作流：MoonSmith 阶段采用完整流程优先的方案 A，
完整 SemaForge 阶段采用可组合阶段命令的方案 B。MoonSmith 首版一次处理一个案例；
无参数显示帮助，使用 `run` 明确启动测试，默认自动选择并记录种子，允许手动指定。
首版使用固定的内置编译配置组合。MoonSmith 阶段尽量固定策略和默认值，减少配置负担，
优先达到既定产品目标完整、稳定且可验收的状态；SemaForge 阶段尽量开放配置能力。
本草案汇总已确定事项与待确认的收敛建议，其余细节留待后续补充。

## 动机

原型的 `run` 将生成、参考比较、自动归约与存证连在一起，`demo` 在同一路径中注入差异，
`replay` 重新执行旧案例。`--budget` 当前只表示归约候选数量，编译与运行超时未通过 CLI 暴露。
这些入口能演示原型，但没有回答新差分流程应如何组织、不同预算如何区分、旧命令如何迁移。

FP-0002 划分生成、执行、判定与存储的责任，要求传递有效预算并保留执行证据。
这些包契约不决定命令树、公开参数和原型入口的替换方式。直接在实现中切换 `run/demo`
会影响使用者和调用脚本对执行步骤、退出状态及产物的理解；同时维护多套入口又会增加文档
与兼容成本，需要单独权衡。

本提案按目标工作流设计 CLI。原型用于识别现状及迁移影响，不作为必须继承的命名或行为基线。

## 设计

### 与已有提案的分工

| 决定 | 归属 |
| --- | --- |
| 工作区成员、包布局、允许依赖及工程检查 | [FP-0001](FP-0001-workspace-modules.md#包的职责与依赖) |
| 生成与差分测试中各包的责任、交接内容及必要保证 | [FP-0002](FP-0002-moonbit-semantic-contract.md#设计) |
| 使用者执行哪些操作、命令如何组合、参数及结果如何呈现 | 本提案 |
| 旧命令、参数和脚本调用方式如何迁移 | 本提案 |

预算是否公开、默认行为及命令验收均由本提案负责；内部包接收显式预算不要求 CLI 提供对应选项。
重执行沿用 FP-0002 的材料与记录契约，本提案设计其产品入口，不重新定义比较结论。
库和应用入口可以先实现并通过直接调用验证，CLI 接入需依据这里确认的工作流完成验收。
不以内部调用通过代替命令行验收。

CLI 负责解析、帮助、终端交互和退出码；[应用层](FP-0001-workspace-modules.md#term-application-layer)
装配生成、执行与存证。语言规则留在适配器，判定规则留在 Engine；命令树不必对应内部包结构。

### 产品原则与决策总表

提案作者确定的产品原则是：MoonSmith 优先完善能力并提供固定策略和默认值，尽量减少
使用者需要作出的配置选择；SemaForge 则尽量提供可配置、可组合的通用能力。
首版单案例只是当前交付范围，MoonSmith 后续仍按既定目标完善功能。固定策略也可以
生成丰富的随机程序；内部算法继续接收显式参数和预算，并记录实际生效值。

下表状态针对 MoonSmith 的当前选择；SemaForge 一栏记录后续方向，具体接口另行设计。
“待确认建议”仅保留为本提案内的接口收敛方案，不表示完整命令表已经确定。

| 决策项 | MoonSmith 阶段 | SemaForge 阶段方向 | 当前状态 |
| --- | --- | --- | --- |
| 工作流程 | 一次完成生成、执行、比较、保存，另有案例重执行 | 各阶段可独立调用和组合 | 已确定 |
| 启动方式 | 无参数显示帮助，`run` 启动测试 | 通用产品入口另行设计 | 已确定 |
| 案例数量 | 首版一次一个，后续按产品需求完善能力 | 批次、并发和停止条件可配置 | 首版已确定 |
| 随机种子 | 自动选择并记录，保留 `--seed` 手动指定 | 扩展种子与批次管理 | 已确定 |
| 生成策略 | 内置模板组合与规则构造，逐步完善语言支持 | 语言范围、生成策略和权重可配置 | 基本方向已确定 |
| 编译配置组合 | 固定内置组合，展示并保存实际配置 | 后端、选项和工具链版本可配置 | 已确定 |
| 规模、深度和构造次数 | 采用内部默认值，不提供独立 CLI 参数 | 分别开放预算配置 | 待确认建议 |
| 编译和执行超时 | 采用内部默认值，记录实际限制和执行事实 | 分阶段配置资源限制 | 待确认建议 |
| 案例保存位置 | 固定默认目录，明确显示产物位置 | 存储位置与组织方式可配置 | 待确认建议 |
| 结果呈现 | 固定简洁摘要，同时保存完整证据 | 输出格式、详细程度和脚本接口可配置 | 待确认建议 |
| 配置来源 | 保持简单命令入口，不增加配置体系 | 统一设计配置入口及覆盖关系 | 沿用首版范围 |
| 后续功能 | 按既定目标完善能力，优先采用内置策略 | 开放策略选择和组合 | 遵循产品原则 |

配置能力的扩展始终遵守程序合法性、比较规则和原始证据保存的共同契约。
具体预算公开范围由本提案确定，不由 FP-0002 的包接口预设。
仅保留 `--seed` 的精简接口仍是建议，不作为已经确定的完整命令表。

### 按产品阶段安排工作流

工作流与[三阶段路线图](../ROADMAP.md#三阶段方向)一致：MoonSmith 采用完整流程优先的
方案 A；第二阶段提取公共库本身不触发命令行工作流切换；完整 SemaForge 产品采用阶段命令
优先的方案 B，届时设计材料交接、参数归属和阶段失败处理。

MoonSmith 在后续阶段继续提供专用体验。两种工作流复用应用层，不复制比较与保存逻辑；
当前按 FP-0001 保持内部职责边界，不提前建设 SemaForge 命令树或公共交接协议。
方案 B 不等于支持任意外部源码，其命令及交接范围在 SemaForge 产品阶段另行设计。

参考 [cargo-fuzz 的运行入口](https://rust-fuzz.github.io/book/cargo-fuzz/guide.html)和
[libFuzzer 对生成运行与已有输入重跑的区分](https://llvm.org/docs/LibFuzzer.html#options)，
可借鉴围绕使用任务组织入口的方法；这些工具的测试对象不同，不能据此直接套用其命令表。

### 首版一次处理一个案例

提案作者选择首版仅支持单个案例：一次新测试生成一个程序，成功生成后对同一程序进行
多配置执行、比较和存证；一次案例重执行也只接收一个已保存案例，追加本次执行记录。
单个案例仍包含多个编译配置的观察，不能把“单个案例”理解为只执行一个配置。

相比同时提供有限批次，单案例范围先验证完整闭环，暂不承担批次种子分配、停止策略和
结果汇总的设计工作。有限批次与持续运行留待后续需求驱动，不属于首版命令范围。
构造尝试次数限制生成器为得到这一个程序付出的工作量，不表示要执行的案例数量。

### 帮助、启动入口与后续扩展

提案作者选择无参数时显示帮助，使用 `run` 明确启动测试。已确认的入口行为如下：

| 调用 | 行为 |
| --- | --- |
| `moonsmith` | 显示帮助、可用操作与常用示例 |
| `moonsmith --help` | 显示帮助 |
| `moonsmith run` | 以有效默认配置启动一次单案例完整测试流程 |

帮助入口只提供使用说明，不启动编译或程序执行，也不创建案例记录。选择显式 `run`
使查看用法与启动测试的意图清楚；不采用无参数直接开始测试的备选行为。
保存案例重执行的职责沿用前文，具体命令及参数细节在后续讨论中补齐。

CLI 后续会随能力增长扩展，首版接口是最小闭环的起点。MoonSmith 新增能力优先融入完整
流程和内置策略，公开选项以实际必要性为依据；完整 SemaForge 阶段再系统开放配置和阶段命令。
这里说明扩展方向，不预定后续命令名称、参数、交接协议或交付版本，也不要求首版提供占位入口。
每次扩展需同步帮助信息、行为说明和验收；改变已有调用语义时需明确兼容与迁移安排。

### 种子的选择与记录

提案作者选择默认自动选择并记录种子，允许通过 `--seed SEED` 手动指定。`run` 未收到
该参数时为本次生成自动选择一个种子；收到合法值时使用该值，不另外选择种子。
与固定默认种子相比，这使日常调用能够探索不同样本，同时保留显式复现生成过程的入口。

自动选择发生在新测试的应用装配阶段，生成算法始终接收显式种子。终端显示实际使用的
种子，并将其与生成器版本、有效生成配置一同保存；生成失败报告也包含已经选定的种子。
手动种子的非法值或缺失值按参数错误处理，不能静默改用自动选择。

生成的可重复性遵循 [FP-0002](FP-0002-moonbit-semantic-contract.md#预算与可重复性的归属)：相同
版本、种子和有效配置产生相同程序，不承诺仅凭种子跨版本重生成。不同种子也可能得到
相同程序，种子不承担案例唯一标识的职责。保存案例重执行直接使用已有材料，不重新
选择种子或重新生成程序。

### 固定的编译配置组合

提案作者选择首版固定一组内置编译配置，不提供配置选择参数。组合至少包含两个行为
约定兼容的配置；具体首发组合沿用 [FP-0002](FP-0002-moonbit-semantic-contract.md#差分比较与证据)
的分工，由实现与可用工具链确定，并在帮助信息中说明。

执行前确定并展示计划配置，保存实际工具链身份、选项和各配置的执行观察。配置不可用、
失败或超时都保留原始事实，并按 FP-0002 判定；不能静默删除未完成的计划配置后宣称全部一致。
固定组合减少首版参数和组合校验的工作量，从内置列表选择配置的能力留作后续 CLI 扩展。
这一选择不要求后续版本永久使用同一组合，各次执行仍须记录实际的计划与结果。

### 公开参数与内部预算

预算的传递与执行遵循 [FP-0002](FP-0002-moonbit-semantic-contract.md#预算与可重复性的归属)：
生成规模、嵌套深度、构造尝试次数，以及编译和程序执行超时分别限制不同资源。
应用层提供有界的有效值并记录，CLI 是否公开相应选项由本提案决定。

按统一决策表，建议把这些预算留作 MoonSmith 内部策略，具体收敛方案留待后续补充。
除已确认的 `--seed` 外，本草案暂不确定其余参数名称、时长写法或公开范围。
种子的允许范围也需与解析规则和帮助信息一致。

默认值与已公开参数的显式值都要得到可记录的有效配置。非法参数应在启动测试前报告具体参数及原因，
不能静默替换成默认值。帮助信息说明公开参数的单位、默认行为、范围和适用操作。
若以后增加批次总时长或归约预算，其含义仍需与单次执行超时、生成预算分别说明。

本轮保持简单命令入口，不增加配置文件、环境变量优先级或插件体系。

### 结果与产物

CLI 必须向使用者区分以下结果，但具体退出码、stdout/stderr 分工及机器可读输出格式仍需设计：

| 情况 | 使用者需要知道的事实 |
| --- | --- |
| 本次结果一致 | 所有计划配置均取得有效且相同的结果；不能表述为已证明编译器正确 |
| 差分不一致 | 哪些配置的有效结果不同，以及查看原始证据的位置 |
| 比较未完成 | 哪些配置未提供有效结果及其原始失败状态；不能把超时当作结果值 |
| 参数或操作错误 | 测试是否已启动、错误原因，以及已经保存的材料位置（若有） |

故障注入需要明确标识。`demo` 是否保留为产品命令、归约是否有独立入口或自动触发，
属于后续命令范围与迁移讨论，不能由旧原型的行为直接决定。
本提案不把新归约算法或任意外部源码执行加入 FP-0002 的最小闭环。

保存后再执行仍以原案例材料为输入，追加新观察并保留原记录；不把重新随机生成一个程序
称为案例重执行。产物路径如何传入和显示由 CLI 设计确定，完整归档格式仍按实际需要另行设计。

## 兼容性

现有可执行入口已在无参数时显示帮助，本提案明确保留该行为。
需要逐项处理现有 `run`、`demo`、`replay` 和参数语义，决定保留、替换或提供迁移期；
尤其不能让原有 `--budget` 在不作说明时从归约次数变成另一种预算。
命令名称、默认操作、退出码和脚本输出发生变化时，需要对应的迁移说明与回归案例。

已有案例和参考结论保持原意，新差分结论来自新执行。CLI 兼容策略不能通过改写历史记录
来制造一致的外观；是否及如何提供旧入口兼容，仍需在后续兼容设计中确定。

本提案进入仓库不触发命令切换；具体命令表、迁移方案和验收预期齐备后再实现产品入口。
产品仍为 MoonSmith，SemaForge 通用 CLI 按[路线图](../ROADMAP.md#semaforge-通用入口)另行推进。

## 验证

下表是确定命令表后需落实的验收范围；草稿检查通过不代表 CLI 设计或实现已完成。

| 场景 | 应观察到的行为 |
| --- | --- |
| 首次使用 | 按帮助信息完成所选工作流，并能找到结果和原始证据 |
| 帮助与启动 | 无参数及 `--help` 显示帮助，不执行编译或创建案例；`run` 才启动新案例测试 |
| 单个案例 | 一次新测试只处理一个生成案例，其多配置观察归入同一案例；重执行一次只处理一个已保存案例 |
| 自动种子 | 未指定种子时选择有效值，终端与案例记录中的值一致；生成失败报告保留已选种子 |
| 指定种子 | 使用显式值；相同生成器版本、种子和有效配置产生相同源码；非法值或缺失值不回退为自动选择 |
| 固定配置组合 | 展示和保存内置计划配置；缺失或失败配置仍保留在计划与证据中，结论遵循 FP-0002 |
| 默认与公开参数 | 默认配置和已公开参数的显式值实际生效且被记录，非法参数在测试启动前失败；不要求每项内部预算都有 CLI 选项 |
| 结果边界 | 一致、差分不一致、比较未完成及操作错误按确定的退出码和输出契约区分 |
| 保存后再执行 | 命令使用保存材料产生新观察，不改写旧案例与旧结论 |
| 旧入口迁移 | 对保留、替换及弃用的行为分别验证说明与实际效果一致 |

预算公开范围、其余命令细节、结果接口和兼容迁移留在本提案中，按后续讨论补充。
本提案保持 Draft；完整调用示例、预期输出及迁移方案齐备后，再推进提案阶段和产品入口实现。
