# 差分归约接入依据

日期：2026 年 10 月 16 日。基线：`59773a9dc20f76365329c0401697afb14361b637`。

基线的 [CLI 工作流原文](https://github.com/zrr1999/moonsmith/blob/59773a9dc20f76365329c0401697afb14361b637/fps/FP-0003-cli-workflows.md)
写过不自动触发归约，混入了内部流程限制。
旧 `Program.candidates` 与参考判断服务于 `int-bool-v1`；当前差分入口使用
`CompleteProgram` 和无参考值的比较，二者没有直接的归约连接。

用户在本任务中明确要求接入归约，并选择“run 发现分歧后自动归约”，不采用独立命令。
用户同时明确：FP-0003 只设计对外行为，不应规定 `run` 内部是否归约。
因此自动接入作为本次应用层实现选择保留，触发、候选和确认细节不写入命令行提案。
归约规则遵循 [Engine 契约](../../../fps/FP-0004-engine-execution-contract.md)，
当前行为记录在 [CLI 模块说明](../../../modules/cli/README.md)和
[原型执行契约](../../../CONTRIBUTING.md#原型执行契约)。
本次不新增 FP；参考判断与差分判断分别保留，避免改变旧记录的含义。

| 选择 | 依据与代价 |
| --- | --- |
| 使用现有 `Reducer` 与 `ReductionSession` | 复用预算和接受规则，避免应用层另写搜索状态机 |
| 固定原配置对 | 输出值可随候选变化，另一对分歧或编译失败不能替代原判据 |
| 为完整程序产生结构候选 | 由语言拥有引用修复和完整检查；本轮不追求穷尽操作或最小性 |
| 重放已保存尝试 | 复用现有源码及构建文件，不需增加 AST 存储、解析外部源码或按种子重生成 |
| 独立归约摘要 | 原始版本 2 案例及尝试格式不变；摘要关联最佳候选、预算和确认，不恢复搜索 |
| 默认 16 个候选加一次确认 | 沿用既有原型预算规模，库参数允许 0 到 64；确认单独计数，不宣称统计稳定性 |

验收覆盖候选类型、作用域与无环关系，固定配置对的保持与失效，预算、原记录保护、
归约保存失败、未确认提示，以及真实工具链上的自动归约和缩减结果重放。
内部故障注入仅用于验证归约流程；它不构成发现真实编译器缺陷的证据。
