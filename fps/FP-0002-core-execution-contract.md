# FP-0002: Core 的职责边界与策略扩展

## 摘要

沿用既有架构，由 Core 负责测试编排、证据判定和归约搜索，语言适配器负责程序表示与语义，
应用装配层连接具体能力，Host 承担进程和文件系统。Core 通过泛型程序值与共享契约协作，
将可替换的搜索策略与必须保持的正确性约束分开。

本提案约定职责、交互关系和可观察保证。具体算法、调度顺序、确认次数、并行度、缓存和存储机制
由后续实现与实验选择；不因某一种实现率先落地就成为本提案的固定要求。
现有原型已提供判定器和泛型归约器，本提案描述其演进目标，不表示以下保证已全部实现。

## 动机

现有[项目设计](../docs/project-proposal.md)和 [FP-0001](FP-0001-workspace-modules.md)已经给出模块边界。
Core 的后续设计需要明确责任如何协作，以及哪些变化可以独立发生。例如，更换归约搜索方法时，
不应重新实现编译器执行、失败判定或案例记录；同一案例出现多种异常时，也不应由各调用方自行
决定保留哪一项。模块依赖图本身不足以保证这些行为。

本轮按各语言具有类似 MoonBit 的程序与工具链能力开展设计，真实差异出现后再扩展。
[调研](../docs/core-research.md)表明，程序改写、搜索调度、候选判定和运行环境适合分别拥有责任；
参考项目的具体算法及性能结论不能直接成为 MoonSmith 的选型或验收依据。

## 设计

### 职责与程序表示

| 组件 | 唯一职责 | 拥有的信息或状态 |
| --- | --- | --- |
| Core | 编排测试、判断证据、决定归约接受与停止 | 测试与搜索进度、判据、预算、当前结果 |
| 语言适配器 | 表达程序语义、构造并检查候选 | 程序表示、合法性规则、参考语义、观察协议及改写上下文 |
| 应用装配层 | 连接具体能力，执行 Core 提出的工作并回传结果 | 能力装配、执行上下文与结果关联 |
| Host | 管理进程、文件系统及外部资源 | 资源句柄、生命周期及实际执行事实 |
| 存储与报告 | 保存证据并据此呈现结果 | 原始案例、追加式执行记录及派生关系 |
| contracts | 表达实际跨组件共享的数据 | 配置、观察、预算、判据与记录的定义 |

Core 通过泛型程序值 `P` 携带程序，不依赖或解释具体 AST。语言知识只由适配器提供，
Core 不重建另一份类型系统。原案例保持不变，变换及归约产生可追溯的派生案例。

以上是责任边界，不规定函数签名、任务枚举、会话编码或新的包结构。

### 编排与执行分离

Core 根据显式配置、预算、随机输入和已有证据决定后续工作；应用层执行并回传事实。
交互区分工作请求、执行证据和派生判断：请求描述需要完成的工作，证据描述实际发生的事情，
判断描述这些证据在给定前提下支持的结论。结果能关联到原案例与执行上下文，未执行的请求不能
充当证据，报告不能自行补全判断。

Core 不直接读取时钟、进程或文件系统，外部中断和资源限制作为执行事实参与后续决定。

采用何种调用接口、任务粒度或并发模型属于实现选择。实现必须说明确定性的适用条件，
不能让宿主随机源或未声明的执行顺序隐式决定测试输入。

### 独立判断与失败保持

各项 Oracle 根据声明的适用条件解释证据，独立保留结论；案例汇总同时表达异常发现和检查完整性。
满足、不满足、不适用和证据不足必须可区分；缺失、超时或基础设施问题不能被补成通过。
异常候选不自动等同于已确认的编译器缺陷。

归约以明确的失败判据为目标。判据表达有关配置、执行阶段和观察关系，独立于展示用指纹。
候选必须具有自身有效的判据证据，不能用失效的参考值、变体或另一类失败替代目标关系。
相同判据持续成立只证明保持了该观察条件，不证明根因相同。

### 分层的策略扩展

归约由以下角色协作。这些是可独立演进的责任，不要求一一对应类型、对象或 package。

| 角色 | 回答的问题 | 边界 |
| --- | --- | --- |
| 语言操作 | 哪些改动有意义，怎样得到合法候选 | 描述操作及其适用上下文，不判断编译器异常 |
| 操作调度 | 接下来探索哪类操作或哪个范围 | 管理调度进度，不接管局部搜索的内部状态 |
| 局部搜索 | 在选定范围内尝试什么，如何利用反馈 | 管理自身搜索状态，不直接执行工具链或宣布接受 |
| 公共引擎 | 候选是否可接受，工作是否可以继续 | 统一管理验证、预算、接受结果和证据记录 |

调度与局部搜索应能分别替换。策略使用语言操作提供的信息提出尝试，引擎回传验证和接受结果，
策略据此继续或结束局部搜索。引擎拥有整体会话的权威状态，策略拥有自身的算法状态；
策略结束不自动等于整个测试或归约会话已经完成。

搜索方法、结果度量和接受规则分别表达。具体方法可以有不同的状态、候选表示和信息需求，
无需共享某个算法的内部结构。实现按需求提供操作或反馈，不预先列出封闭的策略清单。

引擎执行选定的接受规则，同时保持公共约束：原失败判据、合法性要求、整体预算和证据含义
不因策略替换而改变。策略不能自行跳过检查、修改规则或重置限额。对外报告实际结果、停止原因
与保证范围；局部无进展、预算耗尽和全局最小不能混为一谈。

### 确认、预算与证据

确认策略明确如何取得稳定性证据；所需的独立复跑不能由缓存命中代替。结果冲突和证据不足
分别表达，不把未完成确认的候选报告为稳定结果。

各策略声明资源消耗和停止条件，遵守整体预算与取消要求。切换策略不能绕过限额；
没有缩减进展时，原案例及已有证据仍应保留。

原始案例、实际执行和派生判断可追溯，后续尝试追加记录。证据保存失败时不得报告完整交付。
案例重放与搜索状态恢复是不同能力，不要求实现某种日志协议、事务顺序或内部状态持久化。

## 兼容性

保留既有 module、依赖方向、语言 profile、执行矩阵及产品目标。现有原型已有公共函数和
案例、执行记录；落地时需要协调 contracts、Core、app 与报告的结果语义，并保留既有行为的回归验证。
涉及 API 或记录含义的变化时，明确迁移或版本边界；历史 fingerprint 与记录不能自动获得
新失败判据或稳定性保证。

现有原型的候选遍历、严格下降和确认流程保留为实现起点，
不作为 Core 对所有策略的统一要求；职责与可替换边界按本提案表达。

满足本提案的算法替换、参数调整和内部重构属于实现演进；若改变失败保持、证据含义或模块
责任，则依 [FP-0000](FP-0000-governance.md)讨论契约变化。实现选择及实验配置另行记录，
不能通过引用详细设计把具体算法或默认值提升为本提案要求。

[Core 架构设计](../docs/core-architecture.md)解释协作模型；
[调研记录](../docs/core-research.md)保留备选机制和实现候选。两者不替本提案固定策略。

## 验证

后续实现通过行为验证这些边界，不能仅以接口存在或代码编译通过作为验收。

首个验证范围为 Core 库、实际跨组件使用的共享契约与行为测试。通过合成程序、受控执行事实和
可替换策略检验以下行为。新架构与现有 MoonBit 生成器、参考解释器、Host 和 CLI 的集成另行推进；
库的行为测试不能替代真实工具链验证，现有原型闭环也不能替代新契约的验收。

| 场景 | 应观察到的行为 |
| --- | --- |
| 独立更换调度或局部搜索实现 | 复用判定、执行与证据路径，不修改语言语义或复制一套管线 |
| 在声明的确定性条件下重复输入与反馈 | 得到可重现的流程决定，宿主状态不隐式参与随机选择 |
| 同一案例存在多项异常和证据缺口 | 各项结论及完整性同时保留，不用单个结论覆盖，也不补成通过 |
| 候选非法、判据失效或证据不足 | 不能成为保持原失败的接受结果，原因能够追溯 |
| 策略切换、取消、无进展或资源耗尽 | 整体约束仍有效，停止原因明确，原案例与已有证据保留 |
| 确认结果冲突或保存失败 | 如实表达不稳定或未完成，不报告为稳定且完整的交付 |
| 在相同约束下比较搜索方法 | 质量与成本由实际记录推导，结论不超出实验范围 |

具体验收场景见[Core 验收边界](../docs/core-architecture.md#7-验收边界)。
文档检查只验证结构与一致性，不替代算法行为、Host 生命周期或真实编译器实验。
