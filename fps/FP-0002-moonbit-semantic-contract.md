# FP-0002: MoonBit 模板生成与差分测试

## 摘要

首版以发现不同编译配置之间的执行结果不一致为目标：按规则自动组合程序模板，依据类型与
作用域补全程序，再进行多配置执行、比较和证据保存。关键结构先覆盖局部绑定与引用、条件
分支、函数定义与调用；规模与执行预算提供有界默认值并支持调整，配置入口由后续 PR 确定。

本提案只建立上述最小闭环。参考解释器不作为前置条件；程序与输入的产品形式、完整归约
策略、覆盖反馈和外部源码导入留给后续设计。这里定义拟议契约，实际能力以实现与验收证据为准。

## 动机

差分测试可以通过多个编译配置之间的分歧发现异常，无需事先计算每个程序的正确答案。
它仍然依赖有效、可比较的程序，以及足以重新执行案例的材料。首版应把工作集中在这条
路径上，避免将完整参考解释、丰富类型目录和长期扩展机制同时变成生成器的实现门槛。

模板用于安排结构组合与引用关系，规则构造负责补全具体内容。只用少量固定模板会限制
结构变化；完全逐节点随机选择则不便主动安排希望测试的组合。两者共享程序模型与规则，
可以同时支持结构变化和受约束的局部生成。

调研支持这些方法具有可行性，不代表它们在 MoonBit 上的效果已经得到验证：

| 依据 | 可借鉴的方法 | 本提案的取舍 |
| --- | --- | --- |
| [Csmith](https://github.com/csmith-project/csmith) | 生成程序并用差分结果作为判定依据，同时约束程序行为 | 以差分测试为主，保留合法性与可比较性要求 |
| [Xsmith](https://docs.racket-lang.org/xsmith/Xsmith_Guide.html) | 从 AST 空洞开始，按规则填充节点，并继续填充产生的子空洞 | 模板和普通生成共用补全机制，不引入通用语法 DSL |
| [LeJit](https://arxiv.org/abs/2403.11281) | 从已有 Java 代码提取模板，再填充生成程序 | 先按规则组合模板；源码提取及其依赖处理留到后续 |

上述首版重点、混合生成路线、结构范围及预算可配置原则，来自作者在设计讨论中确认的选择。
方案按目标与工作量独立设计，现有实现和申报范围不作为绑定新模型的兼容基线。
这一选择影响语言层生成保证、Engine 的判定依据和应用层的数据流，需要在同一提案中约定。

## 设计

### 首版结构与最小闭环

| 关键结构 | 首版需要表达的关系 |
| --- | --- |
| 局部绑定与引用 | 顺序绑定、词法作用域，以及后续表达式对已有绑定的引用 |
| 条件分支 | 条件决定分支选择；分支可以嵌套，并与绑定、调用组合 |
| 函数定义与调用 | 参数绑定、实参与形参对应、返回结果及函数间调用依赖 |

首版采用无环的函数调用关系；循环与递归的生成和终止约束留给后续扩展。
基础值、具体类型及运算按支撑这些结构的需要选择，本提案不枚举完整类型清单。
实现必须明确实际使用的运算规则和适用配置，不能仅因类型正确就假定行为可比较。

```mermaid
flowchart LR
  T["规则组合模板"] --> G["按类型与作用域补全"]
  G --> V["检查并输出源码"]
  V --> R["至少两个配置执行"]
  R --> C["比较结果"]
  C --> E["保存案例与执行证据"]
```

### 模板与程序共用模型

<a id="term-moonbit-program"></a>

MoonBit 程序是语言适配器拥有的完整程序结构，保留类型、绑定、作用域和调用关系，
可以据此输出源码。完整程序不包含尚待填充的空洞。

<a id="term-program-template"></a>

程序模板是保留部分结构和约束、留有空洞的未完成程序。空洞具有期望类型和所在作用域；
模板还可以约束结构的嵌套及绑定的复用，例如让函数调用结果参与后续条件判断。

模板由结构规则自动组合，补全时沿用相同的类型、作用域和规模规则；填充一个空洞可以
产生新的子结构和空洞。组合过程中维护共享上下文和剩余预算，不能把相互依赖的片段
当作独立文本拼接。从单个空洞开始也是同一生成机制的一种使用方式。

具体 AST、绑定标识和构造 API 由实现选择。本轮不建立独立模板文件格式、插件接口或
跨语言程序表示；后续从自身程序中提取模板时可复用这套模型。
结构与引用关系可由程序检查，但不据此宣称某个分支已执行或某项编译器优化已触发。

### 合法性与可比较性

<a id="term-program-well-formedness"></a>

静态合法性表示程序的类型、绑定和结构自洽：引用指向可见绑定，运算和调用的参数匹配，
分支满足类型规则，函数调用关系符合首版约束。未执行代码也需要满足这些要求。

生成时依据这些规则构造，完成后检查不能由表示本身保证的约束。生成器与检查过程应能
识别未填空洞、悬空引用、类型错误及不支持的结构，无需为此实现完整 MoonBit 类型系统
或参考执行器。官方编译工具提供独立的接受或拒绝观察，拒绝材料应保留供排查。

可比较性还要求同一案例在所选配置下遵循相同的行为约定；时间、随机性、外部状态等
不能成为未记录的结果来源。未明确跨配置行为的构造不进入默认生成范围。
输入如何提供、程序如何组织入口由具体执行方案决定，本提案只要求比较时保持同一案例、
相同输入及约定的环境条件，不固定其产品形式。

### 可配置预算

生成规模、嵌套深度、构造尝试次数，以及编译和程序执行超时均提供有界默认值，并支持调整。
本提案规定预算含义、有效值校验和记录要求，不指定配置入口。具体使用配置文件还是 CLI
参数，以及公开范围、读取方式与覆盖顺序，由后续 PR 决定。命令行工作流与兼容设计见
[FP-0003](FP-0003-cli-workflows.md)。具体数值和允许范围由实现明确，不以存在某个 CLI
选项或某种配置文件作为本提案的验收条件。

模板组合与空洞补全共同消耗生成预算。预算耗尽时明确结束，不能无界重试；执行超时
单独记录，不能当作正常程序结果。有限程序结构也不保证在任意短的时间限制内执行完成。
实际生效的参数，包括使用的默认值，与种子和生成器版本一起保存。
相同生成器版本、种子和有效配置应产生相同程序；不承诺仅凭种子跨版本重生成。

### 差分比较与证据

对同一个已生成案例，至少使用两个行为约定兼容的编译配置取得执行观察。配置可以在
后端、优化设置或工具链版本上不同，具体首发矩阵由实现与可用工具链确定。
源码输出必须保留程序中的结构与绑定含义，不针对某个配置改写测试主体来消除差异。

<a id="term-observation-protocol"></a>

观察协议规定哪些执行输出构成可比较结果，以及如何判断相等。参与比较的配置使用
相同约定，并保留原始输出；具体编码由首个闭环实现选取并记录。

首版至少检测正常完成且可比较的运行结果不一致，按以下规则解释证据：

- 已取得的有效结果中存在分歧时，记录差分不一致及涉及的配置；其他配置的超时或缺失不能掩盖该分歧。
- 所有计划配置都取得有效且相同的结果时，记录本次未观察到不一致，不据此证明程序或编译器正确。
- 其余情况记录为比较未完成；编译失败、崩溃、超时和环境错误分别保留原始事实，不伪装成输出值参与比较。

差分不一致表示需要调查的异常，不自动定位哪个配置出错。不同模板填充结果是不同案例，
它们之间不要求输出相同；本轮不要求参考值、投票定责或完整的故障分类框架。

保存生成源码、案例所需输入与环境条件、有效生成配置、工具链身份与选项，以及各配置的
编译和执行状态、原始输出与比较结论，足以再次执行该案例。重执行使用保存的材料，
保留原案例并追加执行记录；完整归档格式、迁移机制和跨版本重生成另行设计。

职责沿用 [FP-0001](FP-0001-workspace-modules.md#包的职责与依赖)：语言适配器负责模型、
模板、构造规则、检查与源码输出；Engine 负责证据比较；应用层装配配置与保存案例；
Host 负责进程和文件系统。参考求值、归约、变形测试、覆盖反馈及外部源码提取均不阻塞本轮闭环。

## 兼容性

本提案不要求沿用某个既有 AST、生成分布或数值子集，也不改变四模块的依赖方向。
实际 API、CLI 和记录格式变化应在实现中同步调用方与说明。
已有案例及其参考结论保留原意，新的差分结论需来自新的执行证据，不静默改写历史记录。

程序与输入形式、扩展语言结构、模板提取、归约策略和反馈调度按后续实际需求设计；
达到 [FP 门槛](FP-0000-governance.md#何时需要-fp)时另行提案，本轮不预建相关框架。

## 验证

以下是实现后的验收要求，文档检查通过不表示闭环已经实现：

| 场景 | 应观察到的行为 |
| --- | --- |
| 模板组合与补全 | 生成包含绑定、分支及函数调用组合的完整程序；变量引用和参数传递关系可检查，输出源码能在声明配置执行 |
| 错误结构 | 未填空洞、非法引用、类型不匹配及不允许的调用依赖被内部检查识别；保留编译器拒绝材料供排查 |
| 固定生成条件 | 相同版本、种子和有效配置得到相同程序；变化预算可以改变规模，但不能破坏合法性 |
| 预算默认与调整 | 未提供覆盖值时使用已说明的默认值；调整值实际生效并被记录，非法配置被拒绝，预算耗尽有明确结果；不限定配置入口 |
| 真实多配置执行 | 无需参考解释器即可在至少两个兼容配置上完成同一案例的执行、比较和存证 |
| 判定边界 | 用可控观察验证一致、分歧、缺失和超时的区分；第三个配置未完成不掩盖前两个配置已有的分歧 |
| 保存后重新执行 | 能从保存的材料再次执行案例，取得新的观察；原始源码与执行记录保持不变 |

判定测试中的可控差异需标记为测试注入；真实工具链运行与新异常发现分别报告。
验收不以必须发现新的编译器缺陷为前提，也不以模板数量代表测试效果。
相关行为测试和真实执行证据随实现提交；文档门禁按[贡献指南](../CONTRIBUTING.md#常用命令)执行。

AI 辅助范围为资料调研与提案起草；语义与实验结论需人工核验。
