# MoonSmith 行为测试

让测试区分正确行为与一个可信的错误实现；测试数量、内部调用次数和源码形状不替代行为证据。

## 选择契约与观察点

阅读需求、生产调用路径、已有测试及[贡献指南](../../../CONTRIBUTING.md)。结合
[仓库协作约定](../../../AGENTS.md)核对责任归属；沿 [README](../../../README.md)和贡献指南
中的链接读取当前分支已有的相关设计。明确输入或事件顺序、期望结果及测试要捕获的错误。

选择能观察该错误的最窄边界：纯算法用显式输入的单元或性质测试；进程、文件、重放和装配问题
保留必要的真实边界。优先复用所属包的测试与 fixture，不另建没有实际需要的测试框架。
回归测试在可行时证明旧行为失败、修复后通过；不能执行旧行为时说明限制，不编造红绿测试记录。

## 按受影响行为选取用例

- **确定性与预算**：固定种子、配置、版本和预算，检查重复输入得到约定的程序或源码。
  触及调度时改变完成顺序并确认随机流分配不变；检查预算耗尽能有界结束并报告停止原因。
- **语义与判定**：使用已知期望值、独立推导的性质或小型参考模型。核对同一受支持输入的
  可比较性和结果分类；不要复用生产算法生成期望值，也不要只以多个后端一致证明正确。
- **归约**：分别覆盖合法且保留原失败的候选与必须拒绝的候选，例如失去绑定、改变结果分类
  或违反原判据。观察实际接受结果、规模变化和停止原因，避免把局部搜索描述为全局最小化。
- **进程生命周期**：用握手、屏障或可控事件建立竞争顺序，设置有界等待；需要证明超时、
  输出限额或取消清理时，观察实际子进程、后代进程、管道和剩余资源。断言失败也应清理
  测试资源，不用增加 sleep、盲目重试或仅检查取消调用来证明正确。
- **持久化与重放**：使用隔离目录，检查原始源码保持不变、新尝试追加以及记录可读回。
  在实际写入边界注入失败并检查可见状态，不能只检查返回错误；新环境重跑与旧记录分别观察。

只加入能区分不同行为的用例。断言返回值、分类、持久化状态、输出和资源释放；只有精确表示
本身是契约时才比较字节、摘要或快照。测试替身可控制错误条件，但不能替代它所绕过的集成证据。

## 执行与报告

从贡献指南选择聚焦测试及相关仓库检查，执行并调查失败原因。工具缺失、依赖失败、跳过和
零项测试如实记录；不静默更新快照或把未执行的配置计为通过。只改文档或措辞时运行对应检查，
无需为此制造产品测试。

报告覆盖的契约、输入与环境、实际命令和结果。分别说明解析、类型检查、参考求值、产物有效性
及后端执行的证据；把 MoonSmith 自身测试、故障注入与真实编译器案例分开记录。历史案例保留
源码、工具链及执行记录，单次差异只支持异常候选，不能直接称为已确认编译器缺陷。
